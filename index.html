En desarrollo

Qué es ScadLab

Una app de escritorio para diseñar modelos 3D en OpenSCAD conversando con agentes de IA, ver cada versión en un visor 3D y dejar el modelo listo para imprimir en tu Bambu Lab — STL, o 3MF multicolor para el AMS.

  • Claude Code

  • STL · 3MF
  • macOS · Windows
  • Español · English

La idea

OpenSCAD describe un modelo con código: es preciso, paramétrico y se versiona como texto. Lo difícil es escribirlo. ScadLab pone un agente de IA a escribir ese código por ti, y se encarga de lo que rodea a esa conversación:

Cada cambio es un checkpoint

La IA nunca sobrescribe un archivo: cada versión es un .scad nuevo en un árbol con ramas. Volver atrás es hacer clic.

Lo ves al instante

Visor 3D con materiales realistas, medidas, peso y costo estimado de cada pieza.

Los errores se corrigen solos

Si OpenSCAD falla al renderizar, ScadLab le pasa el error al agente para que lo arregle en un checkpoint nuevo.

Pensado para Bambu Lab

Perfil de impresora por proyecto, aviso si no cabe en la placa y 3MF con color por pieza para el AMS.

Tus agentes, no uno nuestro

Usa el CLI que ya tengas instalado —Claude Code, opencode, Codex, Antigravity— o un modelo local con Ollama.

Local

Tus proyectos son carpetas en tu disco y la configuración vive en una base SQLite local. Sin cuenta.

Instalación

Un ejecutable para macOS (Apple Silicon) y otro para Windows (x64). Los binarios no están firmados todavía, así que el sistema avisa la primera vez que los abres.

macOS (Apple Silicon)

  1. Descarga el archivo para macOS desde Releases.
  2. Descomprímelo y arrastra ScadLab.app a Aplicaciones.
  3. La primera vez, clic derecho → Abrir (no doble clic) y confirma en el diálogo.
Gatekeeper

Si macOS dice que la app «está dañada» o «no se puede verificar el desarrollador», es porque no está firmada ni notarizada. Ve a Ajustes del Sistema → Privacidad y seguridad y pulsa Abrir igualmente, o quita la marca de cuarentena desde la terminal:

xattr -dr com.apple.quarantine /Applications/ScadLab.app

Solo hay build para Apple Silicon (M1 y posteriores). En un Mac con Intel no está soportada.

Windows (x64)

  1. Descarga el archivo para Windows desde Releases.
  2. Ejecuta ScadLab.exe (o el instalador, si la versión trae uno).
  3. Si aparece «Windows protegió su PC», pulsa Más información → Ejecutar de todas formas.
SmartScreen

El aviso aparece porque el ejecutable no está firmado con un certificado de código y todavía tiene pocas descargas. No es un diagnóstico de virus. Si prefieres no aceptarlo, compila desde el código fuente.

ScadLab usa WebView2 (el motor de Edge) para su interfaz. Viene incluido en Windows 10 y 11 actualizados; si faltara, la app te lo indica al arrancar.

Compilar desde el código

Necesitas Go, Node.js y la CLI de Wails v2:

go install github.com/wailsapp/wails/v2/cmd/wails@latest
git clone https://github.com/rafael180496/ScadLab.git
cd ScadLab
wails build            # binario en build/bin/

Después de instalar

ScadLab no incluye OpenSCAD: necesitas instalarlo aparte. Sigue con Requisitos.

Requisitos: OpenSCAD y agentes

OpenSCAD es obligatorio: es el que convierte el código en geometría. Los agentes de IA son opcionales, pero son la mitad de la gracia.

OpenSCAD

Descárgalo desde openscad.org. Se recomienda una versión de desarrollo reciente (snapshot) en lugar de la estable 2021.01: renderiza mucho más rápido con el motor Manifold y exporta 3MF con color, que es lo que hace falta para el multicolor.

macOS

brew install --cask openscad@snapshot

Ruta típica:
/Applications/OpenSCAD.app/Contents/MacOS/OpenSCAD

Windows

winget install OpenSCAD.OpenSCAD

Ruta típica:
C:\Program Files\OpenSCAD\openscad.exe

Detección automática Disponible

Al arrancar, ScadLab busca OpenSCAD en las rutas habituales y en el PATH, y muestra la versión que encontró en Configuración. Si lo instalaste en otro sitio, indica la ruta a mano ahí mismo.

Agentes de IA (opcionales)

ScadLab no trae su propio modelo: usa los CLIs que ya tengas instalados y con sesión iniciada. Detecta cualquiera de estos:

AgenteQué necesitas
Claude CodeEl CLI claude instalado y con sesión iniciada
opencodeEl CLI opencode con un proveedor configurado
CodexEl CLI codex con sesión iniciada
AntigravityEl CLI de Antigravity instalado
OllamaOllama corriendo en local (por defecto http://localhost:11434) y un modelo descargado

Cada agente se cobra y se rige por las condiciones de su propio proveedor; ScadLab solo lo ejecuta.

Tu primer proyecto

De una carpeta vacía a una pieza que puedes imprimir: crea un workspace, pídele algo al agente y mira el resultado.

1. Crea el workspace Disponible

  1. Pulsa Nuevo workspace.
  2. Ponle nombre (por ejemplo Caja sensores) y elige una carpeta vacía.
  3. ScadLab crea la estructura y copia las skills para todos los CLIs.

2. Pídele el modelo al agente En desarrollo

Abre una terminal de agente en el workspace y describe la pieza con medidas:

Haz una caja de 60×40×25 mm con paredes de 2 mm y una tapa a presión con holgura de 0,2 mm. Esquinas redondeadas de 4 mm. Caja en azul y tapa en blanco. Debe caber en la A1 mini.

El agente crea 001-base-box.scad, lo valida con el MCP de OpenSCAD y el checkpoint aparece en el árbol. Un checkpoint mínimo se ve así:

// @checkpoint parent= desc="Caja base 60x40x25 con tapa a presion"
/* [Dimensiones] */
width  = 60;   // [20:1:180]
depth  = 40;   // [20:1:180]
height = 25;   // [5:0.5:150]
wall   = 2;    // [1.2:0.2:5]

color("SteelBlue") difference() {
  cube([width, depth, height]);
  translate([wall, wall, wall]) cube([width-2*wall, depth-2*wall, height]);
}

3. Itera

Cada petición nueva genera un checkpoint nuevo: «agrega cuatro agujeros de 3 mm en la base para tornillos M3» crea 002-… con parent=001-…. Si no te gusta, haz clic en el anterior y pide otra cosa: eso crea una rama.

4. Exporta

Con el checkpoint que te guste seleccionado, pulsa 3MF en la cabecera y ábrelo en Bambu Studio. Detalle en Exportar.

Workspaces

Un workspace es un proyecto: una carpeta en tu disco con los checkpoints, la configuración de la impresora y las reglas para los agentes.

Qué hay dentro Disponible

caja-sensores/
├── 001-base-box.scad          # checkpoints: uno por versión
├── 002-m3-holes.scad
├── printer.json               # impresora del proyecto
├── CLAUDE.md                  # reglas para Claude Code
├── AGENTS.md                  # reglas para opencode, Codex, Antigravity
├── lib/                       # librerías (BOSL2, MCAD…) si las usas
├── .claude/skills/            # skills, copiadas para cada CLI
├── .agents/skills/
├── .opencode/skills/
└── .agent/skills/

Es una carpeta normal: puedes abrirla con cualquier editor, versionarla con Git o copiarla a otra máquina. ScadLab la reconoce al volver a abrirla.

Crear, abrir y recientes Disponible

  • Nuevo workspace: nombre + carpeta. Si la carpeta ya tiene .scad, se respetan.
  • Abrir: elige una carpeta existente; ScadLab completa lo que falte (skills, reglas) sin tocar tus archivos .scad.
  • La lista de recientes se guarda en la base local.

Varias ventanas En desarrollo

Hasta 4 ventanas abiertas a la vez, una por proyecto, cada una con sus propias terminales de agente.

Sincronización de skills Disponible

Al crear o abrir un workspace, ScadLab copia las skills incluidas y las tuyas en las cuatro ubicaciones que leen los CLIs. Así da igual qué agente uses: todos siguen las mismas reglas. Ver Skills incluidas.

Checkpoints: el historial En desarrollo

Cada versión del modelo es un archivo .scad inmutable. El historial no está en una base de datos: se reconstruye leyendo los archivos.

El formato

  • Nombre: NNN-slug.scad — número de tres dígitos (el siguiente al mayor que exista) y un slug corto en kebab-case: 001-base-box.scad, 002-rounded-corners.scad.
  • Primera línea, siempre:
// @checkpoint parent=002-rounded-corners.scad desc="Agrega bisagra lateral"

En el primer checkpoint parent= va vacío. desc dice qué cambia respecto al padre, en una frase y sin comillas dobles dentro.

Por qué son inmutables

La IA nunca sobrescribe un checkpoint, ni siquiera uno con error: el arreglo va en uno nuevo. Así cualquier versión que viste sigue existiendo exactamente igual, y comparar o volver atrás no depende de que nadie haya guardado nada. Cada checkpoint es autocontenido (copia todo el código del padre): no hace include de otro checkpoint.

Cargar un checkpoint

Un clic en el árbol lo selecciona y, si nunca se renderizó y el auto-render está activo, lo renderiza. Las mallas quedan en una caché en disco, así que volver a una versión que ya viste no recalcula nada. Ver Renderizar y diagnósticos.

La descripción

Al pasar el ratón sobre un checkpoint, el tooltip muestra su desc: es la forma rápida de saber qué cambió sin abrir el código.

Árbol, ramas y menú En desarrollo

El historial es un árbol, no una lista: puedes volver a cualquier punto y probar otra idea sin perder la anterior.

Ramificar

Selecciona un checkpoint que no sea el último y pídele un cambio al agente. El archivo nuevo toma el siguiente número libre, pero su parent apunta al que elegiste:

001-base-box
├── 002-rounded-corners
│   ├── 003-snap-lid
│   └── 005-alt-screw-lid      # parent=002: rama nueva
└── 004-tall-version           # parent=001

Plegar y conectores

Cada rama se puede plegar para que el árbol no crezca sin fin. Las líneas de conexión dibujan quién viene de quién aunque la numeración salte.

Menú contextual

Renderizar y diagnósticos Disponible

ScadLab corre OpenSCAD sobre cada checkpoint y te dice cómo salió: cuánto tardó, si la malla vino de la caché y, si falló, qué error dio y en qué línea.

Renderizar y cancelar

Elige un checkpoint y pulsa Renderizar en el panel del visor. Mientras corre, el botón pasa a Cancelar. Solo hay un render a la vez por workspace: si eliges otro checkpoint y lo renderizas, el anterior se cancela. Si el render sale bien, la pieza aparece en el visor 3D debajo de la barra de estado; si falla, el panel muestra los diagnósticos.

La barra de estado

DatoQué significa
DuraciónLo que tardó OpenSCAD, en segundos
Desde cachéLa malla no se volvió a calcular: el código y sus include/use no cambiaron desde la última vez. Volver a un checkpoint ya renderizado es inmediato, incluso tras reiniciar la app
Motormanifold o cgal. Si tu OpenSCAD es viejo y no conoce Manifold, ScadLab cae a CGAL solo
VersiónLa versión de OpenSCAD que hizo el render

El estado en el árbol

IndicadorEstado
SpinnerRenderizando
Punto verdeSalió bien
Punto ámbarSalió, pero con advertencias (una variable sin definir, un include que no encontró…)
Punto rojoFalló
Sin puntoTodavía no se renderizó

Al pasar el ratón sobre el indicador se lee el resumen: la duración, cuántas advertencias hubo o el primer error con su línea.

Diagnósticos y salida de OpenSCAD

Si el render tiene errores o advertencias, el panel los lista con su severidad, la línea y el mensaje (y el archivo, si el error está en un include). Un modelo que no genera nada —por ejemplo, todo dentro de un difference() que se resta entero— también cuenta como error. Debajo, Salida de OpenSCAD despliega el texto completo que imprimió OpenSCAD, que se puede seleccionar y copiar.

Auto-render

ScadLab vigila la carpeta del workspace abierto. Cuando aparece un .scad nuevo —por ejemplo, porque un agente lo creó desde la terminal— el árbol se actualiza solo y, con el auto-render activo, ese checkpoint se renderiza sin que toques nada. Si llegan varios a la vez, se renderiza el de número más alto. Elegir en el árbol un checkpoint que nunca se renderizó también lo renderiza. Se apaga en Configuración → OpenSCAD.

RENDER_ERRORS.md

Cuando un render falla, ScadLab escribe RENDER_ERRORS.md en la raíz del workspace: el archivo, los errores con su línea, el código alrededor de cada una, las advertencias y la instrucción de corregirlo en un checkpoint nuevo cuyo padre sea el que falló. Las reglas del workspace le dicen al agente que lo lea. Cuando un render sale bien, el archivo se borra; uno cancelado o sin OpenSCAD no lo toca.

El archivo describe siempre el checkpoint más nuevo, que es sobre el que trabaja el agente. Renderizar uno viejo mientras recorres el historial no lo escribe ni lo borra: abrir un checkpoint roto ya superado no le manda al agente errores que ya corrigió, y abrir uno viejo que anda no esconde que el último está roto. Ver Auto-iteración de errores.

Si OpenSCAD no está

El panel lo avisa con un botón que abre Configuración en la pestaña OpenSCAD, donde puedes indicar la ruta del ejecutable. Si lo instalas con la app abierta, el próximo render ya lo encuentra. Ver Requisitos.

Navegar el modelo Disponible

Cuando un render sale bien, el visor muestra la pieza con materiales PBR y reflejos de entorno sobre la placa de tu impresora, a escala, para que la veas como se verá impresa y no como una malla plana.

La placa

La placa es la de la impresora del workspace, a escala real: cuadrícula de 10 mm (más marcada cada 50 mm) y la caja del volumen de impresión en líneas tenues. La pieza se apoya en la placa y se centra sobre ella, como haría el laminador. El visor usa Z hacia arriba, igual que OpenSCAD.

Ratón y trackpad

GestoAcción
Arrastrar con botón izquierdoOrbitar alrededor del modelo
Arrastrar con botón derecho, o Shift + arrastrarDesplazar (pan)
Rueda, o pellizco en el trackpadZoom

Táctil

Un dedo orbita; con dos, el pellizco hace zoom y el arrastre desplaza.

Teclado

Haz clic en el visor para darle el foco. Las flechas orbitan, Shift+flechas desplazan, + / − hacen zoom, 1–7 eligen las vistas y F encuadra la pieza. El botón ? de la barra del visor recuerda todos los controles. Lista completa en Atajos de teclado.

Cambiar de checkpoint

Al elegir otro checkpoint la cámara se queda donde estaba: así se comparan dos versiones desde el mismo ángulo. Mientras llega la malla nueva sigue a la vista la anterior, y volver a uno ya visto es instantáneo (las mallas quedan en memoria). Si el render del checkpoint falla, el visor se oculta y el panel muestra los diagnósticos; las advertencias de un render que salió bien quedan plegadas en una esquina del visor.

Modos de vista y cámaras Disponible

Wireframe, aristas, proyección ortográfica o en perspectiva y siete vistas predefinidas, todo desde la barra del visor.

Modos de render

  • Sólido (por defecto): materiales PBR con reflejos.
  • Wireframe (W): solo la malla, útil para ver la densidad de triángulos ($fn demasiado alto).
  • Aristas (E): sólido con los bordes de más de 30° marcados, para leer la forma de piezas monocromas.

Ortográfica o perspectiva

El botón Persp / Orto (O) cambia la proyección sin mover la vista. La ortográfica no deforma por la distancia: es la que conviene para comparar medidas o alinear piezas mirando de frente. La perspectiva es la natural para ver el conjunto.

Las siete vistas

  • Frente 1
  • Atrás 2
  • Izquierda 3
  • Derecha 4
  • Arriba 5
  • Abajo 6
  • Iso 7

Cada vista mira la pieza desde ese lado y la encuadra. Abajo es la que se olvida y la que más importa para imprimir: muestra la cara que irá apoyada en la placa (desde abajo la placa se oculta para no taparla). Encuadrar (F) vuelve a centrar la pieza sin cambiar el ángulo.

Medir una pieza: volumen, peso y costo

El panel de la esquina del visor dice cuánto mide la pieza y cuánto material lleva. El peso y el costo de impresión llegan en una fase posterior.

Qué muestra

DatoDe dónde sale
Tamaño X × Y × ZCaja envolvente de la malla, en mm
VolumenVolumen sólido de la malla, en cm³
TriángulosCuántos tiene la malla STL. Muchos suelen ser un $fn demasiado alto
Cerrada / AbiertaSi la malla es estanca (cada arista la comparten exactamente dos caras). Una abierta puede laminarse mal
Peso En desarrolloVolumen × densidad del material, ajustado por el relleno
Costo En desarrolloPeso × costo por kg del material

Hoy las medidas son de la malla entera. Medir cada pieza por separado —cada bloque de primer nivel con su color(), por eso las skills obligan a la IA a colorear todo— llega con el 3MF por piezas En desarrollo. Detalle del cálculo en Estimación de costo.

Colores, captura y vista dividida Disponible

Prueba colores, guarda una imagen del modelo y mira dos ángulos a la vez.

Seis muestras de color

La barra del visor tiene 6 muestras —pensadas como los filamentos que tienes cargados en el AMS—. Un clic pinta la pieza de ese color; doble clic o clic derecho abre el selector para cambiar la muestra, y la paleta se guarda. El color es solo del visor: para que quede en el modelo (y en el 3MF), pídeselo al agente: «cambia la tapa a naranja».

Captura PNG

El botón de la cámara de la barra del visor guarda la vista activa tal como la ves —ángulo, modo y color— en un PNG: ScadLab pregunta dónde guardarlo. Útil para documentar variantes o compartirlas antes de imprimir.

Vista dividida

Parte el visor en dos con una segunda cámara independiente sobre la misma pieza: por ejemplo Iso a la izquierda y Abajo a la derecha, para ver la forma y la cara de apoyo a la vez. Haz clic en una de las dos para activarla (queda con marco naranja): la barra y el teclado actúan sobre la activa, y cada una tiene su propia proyección. La × de la derecha la cierra.

El editor de código Disponible

Monaco —el editor de VS Code, incluido en la app, sin internet— con resaltado de OpenSCAD, buscar y reemplazar, formato automático, autocompletado con la documentación de cada módulo y un linter que revisa el código mientras escribes. Guardar nunca toca el checkpoint: crea uno nuevo.

Solo lectura y modo edición

Un checkpoint es inmutable, así que el código se abre en solo lectura (el candado de la cabecera del panel y de la barra de estado lo dice). Pulsa Editar o haz doble clic en el código para pasar a edición. Mientras editas, el árbol no cambia: el checkpoint sigue siendo el que era hasta que guardes. Descartar (la flecha curva) vuelve al código guardado; si cambias de checkpoint o de workspace con cambios sin guardar, ScadLab pregunta antes de perderlos.

Guardar = checkpoint nuevo

⌘S / Ctrl+S (o Guardar) abre un diálogo corto: el rótulo da el nombre del archivo (007-tornillos-de-la-tapa.scad; el número lo asigna ScadLab) y la descripción va al encabezado @checkpoint. El archivo nuevo es hijo del que estabas viendo, aparece en el árbol, se abre y —con el auto-render activo— se renderiza solo. Igual que si lo hubiera hecho la IA.

Autocompletado y ayuda de cada módulo

Al escribir aparecen los módulos, funciones, palabras clave y variables especiales ($fn, $fa…) de OpenSCAD con su firma y su explicación en tu idioma. Elegir uno abre el paréntesis con el primer parámetro marcado, y la ayuda de firma muestra el resto mientras escribes los argumentos (también con nombre: r = 3 marca r). Pasar el ratón sobre un módulo integrado muestra la misma ayuda.

Buscar y reemplazar

  • ⌘F / Ctrl+F — buscar (también en solo lectura), con mayúsculas, palabra completa y expresiones regulares.
  • ⌥⌘F o ⌘H / Ctrl+H — buscar y reemplazar (en modo edición).
  • Enter / Shift+Enter — siguiente / anterior; Esc cierra.

Formatear

El botón de la varita, ⇧⌥F / Shift+Alt+F o el menú contextual ordenan el código: sangría por llaves y paréntesis, un espacio alrededor de = y de los operadores, nada de espacios al final ni líneas en blanco de más. Es conservador: nunca une ni parte líneas, no toca el interior de strings ni comentarios y respeta la alineación de las anotaciones // [min:paso:max]. Un solo ⌘Z lo deshace. En solo lectura, formatear pasa primero a edición. La sangría (2 o 4 espacios) se elige en Configuración → General → Editor de código.

El linter

Mientras editas —y una vez al abrir cada checkpoint— ScadLab revisa el código: primero con el parser del propio OpenSCAD (errores de sintaxis, variables y módulos desconocidos, include que no existen) y después con sus reglas propias, pensadas para imprimir y para el flujo de checkpoints. Los problemas se subrayan (rojo: error, ámbar: advertencia, azul: sugerencia) y al pasar el ratón se lee el mensaje con su código.

Agentes en la terminal En desarrollo

Una terminal integrada que ejecuta el agente que prefieras dentro del workspace. El agente escribe checkpoints y tú los ves aparecer en el árbol.

Qué agentes

Claude Code, opencode, Codex y Antigravity — solo los que estén instalados: la detección (ya disponible) decide qué aparece en el selector. Para chat con un modelo local está Ollama.

Sesiones

  • Ver las sesiones anteriores del workspace.
  • Retomar una sesión con su contexto, también desde el menú de un checkpoint.
  • Nueva sesión cuando quieras empezar limpio.

Límites

Hasta 2 terminales por ventana —por ejemplo una con Claude Code y otra con Codex comparando enfoques— y hasta 4 ventanas.

Reglas del workspace: CLAUDE.md y AGENTS.md En desarrollo

Cada workspace lleva un archivo de reglas que el agente lee al empezar. Es lo que garantiza que el historial no se rompa, use el agente que use.

Qué archivo lee cada agente

  • CLAUDE.md — Claude Code.
  • AGENTS.md — opencode, Codex y Antigravity.

Las reglas obligatorias

  1. Nunca sobrescribir ni borrar un .scad: cada cambio es un checkpoint nuevo.
  2. Usar colores: toda pieza de primer nivel dentro de color(...).
  3. Validar cada checkpoint con el MCP de OpenSCAD antes de darlo por terminado.
  4. Parámetros arriba, con comentarios de Customizer; todo en milímetros.
  5. Respetar printer.json: el modelo tiene que caber en la placa.
Consejo

Puedes añadir reglas propias al final del archivo —«usa siempre insertos M3 de 4,2 mm», «nada de voladizos mayores de 45°»—, pero no quites las obligatorias: son las que mantienen el árbol de checkpoints coherente.

Servidor MCP de OpenSCAD En desarrollo

Un servidor MCP que le da al agente herramientas para renderizar y validar con el mismo OpenSCAD que usa la app. Se configura solo en cada workspace.

Qué le permite al agente

  • Renderizar un checkpoint y recibir los errores y advertencias de OpenSCAD.
  • Comprobar que el resultado cabe en la impresora del workspace.
  • Exportar a STL o 3MF.

Sin el MCP, el agente tendría que adivinar si su código compila. Con él, lo comprueba antes de decirte que terminó.

Configuración automática

Al crear o abrir un workspace, ScadLab escribe la entrada del servidor en el archivo de configuración que lee cada CLI (por ejemplo .mcp.json para Claude Code), apuntando a la ruta de OpenSCAD de tu configuración. No tienes que tocar nada.

Auto-iteración de errores En desarrollo

Si un checkpoint no renderiza, ScadLab se lo dice al agente y le pide que lo corrija — sin que tengas que copiar el error.

Lo que ya hace Disponible

Cuando un agente crea un checkpoint, ScadLab lo renderiza solo y, si falla, deja RENDER_ERRORS.md en el workspace; las reglas del workspace le dicen al agente que lo lea. Lo que falta es el aviso automático en la terminal del agente (paso 3). Detalle en Renderizar y diagnósticos.

Cómo funciona

  1. El agente crea 004-add-hinge.scad y ScadLab lo renderiza.
  2. OpenSCAD falla. ScadLab escribe RENDER_ERRORS.md en el workspace con el archivo, la línea y el mensaje.
  3. Le pide al agente activo que lo lea y lo arregle.
  4. El agente crea 005-fix-hinge.scad con parent=004-…. El 004 queda como estaba.
# RENDER_ERRORS.md
Archivo: 004-add-hinge.scad
ERROR: Parser error in file 004-add-hinge.scad, line 31: syntax error
Corrige el error en un checkpoint NUEVO con parent=004-add-hinge.scad.
Por qué un checkpoint nuevo

Corregir en el lugar rompería la regla de inmutabilidad y perderías la pista de qué intentó la IA. Así el árbol muestra también los tropiezos.

Crear tu propia skill Disponible

Si siempre le explicas lo mismo al agente —tus tornillos, tu estilo, tus piezas estándar—, conviértelo en una skill y deja de repetirlo.

Crearla desde Configuración

  1. Ve a Configuración → Skills y pulsa Nueva skill.
  2. ScadLab parte de la plantilla _skill-template: te pide nombre (kebab-case) y descripción.
  3. Edita el SKILL.md generado. Al abrir cualquier workspace, la skill se copia junto con las incluidas.

El formato de SKILL.md

---
name: mis-insertos-m3
description: Medidas de agujeros para insertos térmicos y tornillos M3 de mi taller.
  Úsala SIEMPRE que el modelo lleve tornillos, insertos o tuercas.

# Insertos y tornillos M3

- Inserto térmico M3 × 5 mm: agujero de 4,2 mm, profundidad 5,5 mm.
- Paso de tornillo M3: 3,4 mm. Cabeza avellanada: 6,5 mm a 90°.

  • No contradigas a openscad-core: sus reglas son el contrato con la app.

}

Multicolor con AMS

Una pieza por color en OpenSCAD, un 3MF con esas partes, y en Bambu Studio cada parte va a un filamento del AMS o AMS lite.

La regla: una pieza por color

Cada bloque de primer nivel va dentro de su color(), y las piezas no deben solaparse: donde dos colores ocupan el mismo volumen, el slicer no sabe cuál poner. Resta una de otra si se tocan:

// @checkpoint parent= desc="Placa con nombre bicolor"
/* [Placa] */
w = 80; d = 25; h = 3;
txt = "LUCIA";
relief = 1;

module label() {
  translate([w/2, d/2, h - relief])
    linear_extrude(relief) text(txt, size = 11, halign = "center", valign = "center");
}

color("White") difference() { cube([w, d, h]); label(); }   // base con el hueco
color("Black") label();                                    // texto que llena el hueco

Aquí el texto está embutido en la base (misma altura total): sale plano y se imprime sin cambios de altura entre colores.

Exportar En desarrollo

El botón 3MF genera el archivo con una parte por color, que Bambu Studio abre con las partes asignables a filamentos. Requiere una versión de OpenSCAD que exporte 3MF con color (ver Requisitos).

Cuántos colores

AMS lite (A1, A1 mini): 4. AMS: 4 por unidad, hasta 16 encadenando unidades. Cada cambio de color purga filamento: menos colores y menos capas con cambio es más rápido y desperdicia menos.

Estimación de costo En desarrollo

Una cifra rápida para decidir antes de abrir el slicer: cuánto pesa la pieza y cuánto cuesta imprimirla.

Cómo se calcula

  1. Volumen sólido de la pieza (cm³), de la malla renderizada.
  2. Volumen efectivo: el sólido no se imprime macizo; se ajusta según el % de relleno configurado (las paredes cuentan enteras).
  3. Peso = volumen efectivo × densidad del material.
  4. Costo = peso ÷ 1000 × costo por kg.

Ejemplo

Una caja de 42 cm³ sólidos en PLA (1,24 g/cm³) que, con 15 % de relleno, queda en unos 17 cm³ efectivos: ≈ 21 g. Con PLA a 20 €/kg, ≈ 0,42 €.

Densidades por defecto

MaterialDensidad (g/cm³)
PLA1,24
PETG1,27
ABS1,04
ASA1,07
TPU1,21

Densidad, costo/kg y relleno se cambian en Configuración → Materiales.

Es una estimación

No conoce tus perímetros, capas superiores ni la purga de los cambios de color. Para el número exacto, el que da Bambu Studio al laminar.

Preguntas frecuentes

¿Necesito saber OpenSCAD?

No para empezar: describes la pieza y la IA escribe el código. Saber leerlo ayuda a pedir cambios precisos («sube wall a 2,4»), y el editor te deja tocarlo a mano.

¿Necesito una suscripción de IA?

Para los agentes de terminal, la que pida cada CLI (Claude Code, Codex…). Si no quieres pagar, usa Ollama en local, con menos precisión.

¿Por qué la IA no puede editar un checkpoint?

Porque el historial se reconstruye de los archivos: si uno cambiara, el árbol dejaría de decir la verdad. Ver por qué son inmutables.

¿Funciona con impresoras que no son Bambu Lab?

El STL sirve para cualquier slicer y las reglas FDM son las mismas. Lo específico de Bambu son los perfiles incluidos y el flujo de 3MF multicolor con AMS.

Exporté a 3MF y Bambu Studio no muestra los colores

Comprueba que cada pieza de primer nivel tiene su color(), que no se solapan, y que tu OpenSCAD es una versión reciente que exporta color en 3MF (Requisitos). Al importar, acepta cargarlo como un objeto con varias partes.

¿Hay versión para Linux o Mac con Intel?

No se publican binarios para esas plataformas. Puedes intentar compilar desde el código, sin soporte.

¿Dónde están mis modelos si desinstalo la app?

En las carpetas de tus workspaces, intactos. Solo se pierde la configuración de scadlab.db; ver Dónde se guardan tus datos.

¿Por qué hay temas «En desarrollo»?

La v0.1.0 es la fundación de la app. La ayuda documenta de antemano lo planificado para que se vea a dónde va el proyecto; la insignia desaparece cuando la función llega.
