What ScadLab is

A desktop app for designing 3D models in OpenSCAD by talking to AI agents, watching every version in a 3D viewer and getting the model ready to print on your printer — STL, or multicolor 3MF for the AMS, the MMU, the CFS and the other systems.

The idea

OpenSCAD describes a model with code: it is precise, parametric and versioned as text. The hard part is writing it. ScadLab gets an AI agent to write that code for you, and takes care of everything around that conversation:

Every change is a checkpoint

The AI never overwrites a file: each version is a new .scad in a tree with branches. Going back is one click.

You see it instantly

A 3D viewer with realistic materials, measurements, and the estimated weight and cost of each part.

Errors fix themselves

If OpenSCAD fails to render, ScadLab hands the error to the agent so it fixes it in a new checkpoint.

For your printer, whatever the brand

A catalog of seven brands, printer, colors and skills per workspace, a warning when it does not fit on the plate, and a 3MF with one color per part.

Your agents, not ours

Use the CLI you already have installed —Claude Code, opencode, Codex, Antigravity— or a local model with Ollama.

Local

Your projects are folders on your disk and the settings live in a local SQLite database. No account.

Install

One executable for macOS (Apple Silicon) and another for Windows (x64). The binaries are not signed yet, so the system warns you the first time you open them.

Version 0.2.0

The files are on Releases: ScadLab-v0.2.0.dmg for macOS and ScadLab-v0.2.0-windows-amd64.exe for Windows. You can also build it from source.

macOS (Apple Silicon)

  1. Download the .dmg for macOS from Releases.
  2. Open it and drag ScadLab.app to Applications.
  3. The first time, right-click → Open (not a double-click) and confirm in the dialog.
Gatekeeper

If macOS says the app “is damaged” or “cannot be verified”, it is because it is not signed or notarized. Go to System Settings → Privacy & Security and click Open Anyway, or remove the quarantine flag from the terminal:

xattr -dr com.apple.quarantine /Applications/ScadLab.app

There is only an Apple Silicon build (M1 and later). It is not supported on an Intel Mac.

Windows (x64)

  1. Download the file for Windows from Releases.
  2. Run the .exe: it is portable, no installer needed.
  3. If “Windows protected your PC” appears, click More info → Run anyway.
SmartScreen

The warning appears because the executable is not signed with a code certificate and has few downloads so far. It is not a virus diagnosis. If you would rather not accept it, build from source.

ScadLab uses WebView2 (Edge's engine) for its interface. It ships with up-to-date Windows 10 and 11; if it is missing, the app tells you at startup.

Build from source

You need Go, Node.js and the Wails v2 CLI:

go install github.com/wailsapp/wails/v2/cmd/wails@latest
git clone https://github.com/rafael180496/ScadLab.git
cd ScadLab
wails build            # binary in build/bin/

After installing

ScadLab does not need OpenSCAD to open: without it, it renders with its built-in engine, and you can download OpenSCAD from the app itself. Continue with Requirements.

Requirements: OpenSCAD and agents

OpenSCAD is what turns the code into geometry, and ScadLab brings a built-in copy to fall back on, so the 3D viewer works even if you have not installed it. The AI agents are optional, but they are half the fun.

OpenSCAD

Download it from openscad.org. A recent development version (snapshot) is recommended over the stable 2021.01: it renders much faster with the Manifold engine and exports 3MF with color, which is what multicolor needs.

macOS

brew install --cask openscad@snapshot

Typical path:
/Applications/OpenSCAD.app/Contents/MacOS/OpenSCAD

Windows

winget install OpenSCAD.OpenSCAD

Typical path:
C:\Program Files\OpenSCAD\openscad.exe

Automatic detection Available

At startup, ScadLab looks for OpenSCAD in the usual locations and in the PATH, and shows the version it found in Settings. If you installed it somewhere else, enter the path by hand right there.

No OpenSCAD installed: built-in engine and download Available

If ScadLab does not find OpenSCAD, it does not stop working: it renders with a built-in engine, the official OpenSCAD 2025.12.30 compiled to WebAssembly. The 3D viewer, the STL and 3MF export (with one part per color) and the weight and cost estimate work the same; it is only slower. The render panel says so with an informational notice, and the status bar shows a WASM 2025.12.30 badge.

To render faster, click Download OpenSCAD (in that notice or in Settings → OpenSCAD). ScadLab downloads OpenSCAD 2025.12.30 from openscad.org (about 60 MB on macOS and 40 MB on Windows), checks its SHA-256, and installs it in its own data folder: it does not touch the rest of your system or ask for administrator permissions. While it runs you see the progress and can Cancel; a cancelled or failed download leaves nothing behind. When it finishes, the active checkpoint is rendered again with the real OpenSCAD.

Order of searchWhat is used
1The path you set in Settings → OpenSCAD
2The OpenSCAD downloaded by ScadLab
3The one in your PATH and in the usual install locations
4The built-in engine (OpenSCAD on WebAssembly)

Remove download deletes only what ScadLab downloaded, never an OpenSCAD you installed. The download exists for macOS (Apple Silicon and Intel) and Windows (64-bit); on other systems, install OpenSCAD yourself.

License. OpenSCAD is free software under the GPL license. The built-in engine is the official one, unmodified, and ScadLab (MIT) includes it as a separate program; the version, the SHA-256, the license and where the source code is are listed in THIRD_PARTY_NOTICES.md. The OpenSCAD you download is not distributed by ScadLab: it comes straight from openscad.org.

Your first project

From an empty folder to a part you can print: create a workspace, ask the agent for something and look at the result.

1. Create the workspace Available

  1. Click New workspace.
  2. Give it a name (for example Sensor box) and pick the printer; if it is multicolor, say how many colors it uses. The skills come checked for your printer and you can adjust them.
  3. Under Location choose the folder it is created in (Choose…): by default it is the one from Settings → General, and it is created if it does not exist. Below, Will be created in shows the exact final path (<location>/sensor-box) as you type the name; if that folder already exists and is not empty, ScadLab leaves it alone and tells you which one it is.
  4. ScadLab creates the structure and copies only the chosen skills for every CLI.

The workspace is never opened empty: it comes with 001-<name>.scad, a base with a knob, with Customizer parameters and two colors. A workspace you open that has no .scad at all (one from before this version, for example) gets it too. If you emptied it —sent its checkpoints to the trash, or emptied the trash afterwards— it does not come back on its own: the viewer and the Code panel show Create a starter model when the project has no checkpoint, and write it when you ask. It never overwrites anything. Next to it, Create from an image starts the project from your photos.

2. Ask the agent for the model Available

Open the Agent panel, pick your agent, click New and describe the part with measurements:

Make a 60×40×25 mm box with 2 mm walls and a snap-fit lid with a 0.2 mm clearance. 4 mm rounded corners. Blue box and white lid. It must fit on the A1 mini.

The agent creates 001-base-box.scad, ScadLab renders it on its own and the checkpoint shows up in the tree; if it fails, the agent gets the notice to fix it (auto-iteration). A minimal checkpoint looks like this:

// @checkpoint parent= desc="Base box 60x40x25 with snap-fit lid"
/* [Dimensions] */
width  = 60;   // [20:1:180]
depth  = 40;   // [20:1:180]
height = 25;   // [5:0.5:150]
wall   = 2;    // [1.2:0.2:5]

color("SteelBlue") difference() {
  cube([width, depth, height]);
  translate([wall, wall, wall]) cube([width-2*wall, depth-2*wall, height]);
}

3. Iterate

Every new request produces a new checkpoint: “add four 3 mm holes in the base for M3 screws” creates 002-… with parent=001-…. If you do not like it, click the previous one and ask for something else: that creates a branch.

4. Export

With the checkpoint you like selected, click 3MF in the header and open it in Bambu Studio. Details in Export.

Workspaces

A workspace is a project: a folder on your disk with the checkpoints, the printer settings and the rules for the agents.

It is a regular folder: you can open it with any editor, version it with Git or copy it to another machine. ScadLab recognizes it when you open it again.

Create, open and recents Available

  • New workspace: name, printer and colors, skills and location (the folder that will hold it; the workspace ends up in <location>/<lowercase-hyphenated-name>). Use this folder as the default makes the next ones start there. A destination folder that already exists and has files in it is refused without touching it.
  • Open: choose an existing folder; ScadLab fills in whatever is missing (skills, rules) without touching your .scad files.
  • A first .scad out of the box: a new workspace —and a folder you open that has no .scad at all— starts with a valid 001-<name>.scad (checkpoint header, $fn, Customizer parameters and a color() part that renders), already selected. If the folder already had .scad files, nothing is added or touched.
  • The recents list is stored in the local database.

Several projects: project tabs Available

You can have up to 4 projects open at once, each in its own tab, in the header, to the right of the logo. It is a single window: no new system windows are opened.

  • Open another: the + button in the header lists your workspaces (the ones already open carry a mark and take you to their tab) and offers New workspace…. Clicking a workspace in the sidebar also opens it as a tab. With 4 open the + is disabled, and its hint tells you to close one.
  • Switching tabs is instant and loses nothing: each project keeps its selected checkpoint, its unsaved code (and whether you were editing), the open comparison with the parent, the part selected in the viewer and the chat you had. The sidebar, the viewer, the code, Problems, Print and the chat follow the project in front.
  • Background ones keep working: their folder is still watched, auto-render keeps responding to whatever an agent writes, and their agents and auto-iteration keep running. The Agent 1 and Agent 2 panels show the terminals of the active project (up to 2 per project, 8 in total); the other projects' terminals stay alive, with their screen intact, until you go back to them.
  • Reorder: drag a tab, or use its menu (right-click): Move left / Move right, Close, Close the others and Show in Finder (in Windows, in Explorer).
  • Close with the × or the shortcut: if the project has unsaved changes or running agents, ScadLab tells you what will be lost before closing (the agents are stopped). Closing the last one leaves an empty screen.
  • When ScadLab opens, it reopens the tabs you had and the one that was in front.

In narrow windows (or with a larger interface) the tabs shorten with an ellipsis and keep only the most important indicator; they never push the export buttons out of the window. Hover over a tab to see the full name and its folder.

Each agent sees the other open projects

When you open an agent from ScadLab, the folders of the other projects open at that moment are added to it (--add-dir in Claude Code, Codex and Antigravity), and its rules tell it that it can read them to reuse parts but only writes in its own. Two caveats:

  • opencode has no equivalent option: it only sees its own project's folder.
  • The folders are fixed when the agent is opened: if you open another project afterwards, an agent that was already open does not find out. Click New in its terminal to relaunch it with the current list.

What ScadLab remembers when you quit Available

When you open the app again everything is as you left it, with nothing to save by hand:

  • Projects and checkpoint: the open tabs, which one was in front and, in each project, the checkpoint you had selected (not the newest one; if that file no longer exists, the latest one is opened).
  • Panels: the layout (splits, floating or hidden panels), which tab was active in each group, the maximized panel and the minimized groups. Focus mode is not remembered: ScadLab always opens with your panels.
  • Window: the sidebar width, whether it was hidden, and the status bar.
  • 3D viewer: wireframe, edges, orthographic or perspective projection, split view, the chosen color swatch and whether the part is painted with the model's own colors, and the collapsed measurements. Not the camera: each part is framed on its own.
  • Appearance: theme, interface size and the editor, terminal and chat fonts.

Skills sync Available

When you create or open a workspace, ScadLab copies the included skills and your own into the four locations the CLIs read. That way it does not matter which agent you use: they all follow the same rules. See Included skills.

Checkpoints: the history Available

Every version of the model is an immutable .scad file. The history is not in a database: it is rebuilt by reading the files.

The format

  • Name: NNN-slug.scad — a three-digit number (the one after the highest that exists) and a short kebab-case slug: 001-base-box.scad, 002-rounded-corners.scad.
  • First line, always:
// @checkpoint parent=002-rounded-corners.scad desc="Adds a side hinge"

In the first checkpoint parent= is empty. desc says what changes from the parent, in one sentence and with no double quotes inside.

Why they are immutable

The AI never overwrites a checkpoint, not even one with an error: the fix goes in a new one. That way any version you have seen still exists exactly as it was, and comparing or going back does not depend on anyone having saved anything. Each checkpoint is self-contained (it copies all the parent's code): it does not include another checkpoint.

Loading a checkpoint

One click in the tree selects it and, if it was never rendered and auto-render is on, renders it. The meshes are kept in a disk cache, so going back to a version you already saw does not recompute anything. See Rendering and diagnostics.

The description

When you hover over a checkpoint, the tooltip shows its desc (the quick way to know what changed without opening the code), the file, who created it —the agent and the session, or “Saved from the chat”— and when.

What ScadLab stores next to the checkpoints

The workspace's .scadlab/ folder holds two things that are not models: the trash and the active parent (.scadlab/active-parent, one line with a file name). Labels, folding and the link to the agent's session live in the local database scadlab.db: if you lose it, the tree is rebuilt anyway by reading the files and only those details go. Neither touches your .scad files.

Tree, branches and menu Available

The history is a tree, not a list: you can go back to any point and try another idea without losing the previous one. Right-click a checkpoint (or click “…” when hovering) for everything that follows.

Branching and the active parent

The active parent is the checkpoint the next one created hangs from, whether it is made by the agent in the terminal, the chat, the MCP server or you when saving from the editor. It is marked in the tree with a branch icon. To branch, right-click the checkpoint you want to start from and choose Branch from here: the agent reads it from .scadlab/active-parent (the workspace rules say so) and the create_checkpoint tool uses it by default.

  • It advances on its own. When a child of the active one is created, the new one becomes the active one: you keep working on the same branch without marking it again. A variant that comes off another parent does not move the active one.
  • With no active parent, the usual rule applies: the next one hangs from the newest checkpoint, and the tree marks that one.
  • If you send the active one to the trash, the active one becomes its parent.
001-base-box
├── 002-rounded-corners
│   ├── 003-snap-lid            # active parent: the next one hangs from here
│   └── 005-alt-screw-lid      # parent=002: new branch
└── 004-tall-version           # parent=001

Rename

Renaming changes the label: the name shown in the tree, up to 80 characters. The file does not get renamed, because its children name it in their parent= and a checkpoint is immutable. Enter saves, Esc cancels, and leaving it empty shows the file name again.

The trash

Sending a checkpoint to the trash does not delete it: it moves to the workspace's .scadlab/trash/, with the date in front of the name. The trash icon in the tree header shows how many there are and opens the list, with each one's description, when it was discarded and the Restore button. Deleting for real is a separate decision, and only yours: see below.

  • Restoring puts the checkpoint back under its name; if that number is already taken by another, it takes the next free one with the same slug. The file itself is not rewritten.
  • Its children are not left orphaned. When you send it to the trash, its direct children hang from its parent —the “grandparent”— or, if it was a root, become roots. Only the // @checkpoint parent=… line of each child changes: the code, the description and the file date are untouched, and grandchildren keep hanging from their own parent. Restoring undoes it: children that are still where they were left hang from the restored one again (under the name it came back with); one you already moved to another branch is left alone. If you send the whole branch to the trash, there is nothing to re-hang.
  • If it was the active parent, the active one becomes its parent.

A child whose parent is gone: “Make root”

A workspace that already had children whose parent is in the trash (from an earlier ScadLab version), or a parent deleted by hand, shows them with ⚠ in the tree, and the Problems panel warns SL002. If the parent is in the trash the warning says so: you can restore it from the trash or press Make root —on the warning, or by right-clicking the checkpoint—, which leaves it with no parent by rewriting only its header line.

Delete for good and empty the trash

The trash window has two buttons that do delete, and they ask for confirmation naming what goes and saying it cannot be undone:

  • ✕ on each row: deletes that checkpoint for good.
  • Empty trash: deletes everything in that workspace's .scadlab/trash/ —the checkpoints and any other file someone left there—. Emptying it does not bring the starter model back when you reopen a workspace left with no models: you left it empty on purpose, and the “Create a starter model” button is still there.

This is interface-only: the AI can send to the trash and restore, but none of its tools deletes for good or empties the trash. (The skills trash is a different one and has no such button.)

Compare with the parent

The Source panel turns into a read-only diff viewer: the parent on the left, the checkpoint on the right, with what was added and removed highlighted and the rest folded. In a narrow panel it is shown in a single column; the bar button switches it by hand. Back to code (or choosing another checkpoint) closes it.

Resume the session that created it

When a new checkpoint appears and there is an agent terminal open in that workspace, ScadLab stores which agent and which session created it (that agent's most recent one for the folder). The ones you save from the chat remember the chat. Afterwards, Resume session opens the agent in the terminal with that conversation (--resume) or opens the chat. What you save yourself from the editor is not attributed to the agent, and Antigravity, which does not list its sessions, cannot be resumed by id.

Folding and connectors

Each branch can be folded so the tree does not grow endlessly. The connector lines draw who comes from whom even when the numbering jumps.

With the keyboard

With the focus on a checkpoint in the tree: ↑ ↓ move, ← → fold and unfold, Enter selects it, F2 renames it, ⌫ / Del sends it to the trash (with confirmation) and the menu key or Shift+F10 opens the menu. These keys belong to the tree: with the focus in the editor or the terminal they do nothing. See Keyboard shortcuts.

Rendering and diagnostics Available

ScadLab runs OpenSCAD on each checkpoint and tells you how it went: how long it took, whether the mesh came from the cache and, if it failed, what error it gave and on which line.

Render and cancel

Choose a checkpoint and click Render in the viewer panel. While it runs, the button turns into Cancel. There is only one render at a time per workspace: if you choose another checkpoint and render it, the previous one is cancelled. If the render succeeds, the part appears in the 3D viewer below the status bar; if it fails, the panel shows the diagnostics.

Diagnostics and OpenSCAD output

If the render has errors or warnings, the panel lists them with their severity, the line and the message (and the file, if the error is in an include). A model that produces nothing —for example, everything inside a difference() that is subtracted away entirely— also counts as an error. Below, OpenSCAD output expands the full text OpenSCAD printed, which can be selected and copied.

Auto-render

ScadLab watches the open workspace's folder. When a new .scad appears —for example, because an agent created it from the terminal— the tree updates on its own and, with auto-render on, that checkpoint is rendered without you touching anything. If several arrive at once, the one with the highest number is rendered. Selecting in the tree a checkpoint that was never rendered also renders it. Turn it off in Settings → OpenSCAD.

RENDER_ERRORS.md

When a render fails, ScadLab writes RENDER_ERRORS.md at the workspace root: the file, the errors with their line, the code around each one, the warnings and the instruction to fix it in a new checkpoint whose parent is the one that failed. The workspace rules tell the agent to read it. When a render succeeds, the file is deleted; a cancelled one, or one without OpenSCAD, does not touch it.

The file always describes the newest checkpoint, which is the one the agent is working on. Rendering an old one while you browse the history neither writes nor deletes it: opening an already superseded broken checkpoint does not send the agent errors it already fixed, and opening an old one that works does not hide that the latest is broken. See Auto-iteration on errors.

If OpenSCAD is missing

It does not stop you: ScadLab renders with its built-in engine and the panel shows an informational notice (not an error) with the version and the reason, and the Download OpenSCAD button with its progress and Cancel. The status bar shows WASM 2025.12.30. Only if the built-in engine cannot start either does the panel report that nothing can be rendered, with the download button and another that opens Settings on the OpenSCAD tab, where you can enter the executable's path. If you install it while the app is open, the next render finds it. See No OpenSCAD installed.

Edit an STL Available

Bring in an STL, 3MF or OBJ model, move it, cut it and add pieces or holes —by hand or by asking the AI— without ever touching the original file.

The file is never touched: every edit is a checkpoint

The STL stays intact in the workspace's refs/ folder. Every change is OpenSCAD code in a new checkpoint that does import("refs/part.stl") and applies the operations to it. That is why an edit sits in the tree with its parent, is undone by going back to the previous checkpoint, is rendered with OpenSCAD or the built-in engine and can be exported to STL or 3MF like any other.

Import a model Available

There are two ways: the Import STL/3MF/OBJ… button in the sidebar (next to the checkpoint buttons) or dragging the file onto the window. Before bringing it in, a dialog analyzes the file and shows its size, triangles, volume, whether the mesh is closed and, for a 3MF, its colors. It also warns about what matters for editing: an open mesh, one with more than 500,000 triangles, a 3MF with several colors (it is flattened into one mesh and loses them) or a part that does not fit your printer's plate.

"Center and rest on the plate" (ticked by default) adds a translate() to the base checkpoint: the model ends up in the middle of the plate resting on Z = 0, and the original file does not change. A 3MF or OBJ is converted to STL in refs/ (the original stays next to it). After importing, the new checkpoint is a root of the tree and is selected.

Edit mode

The Edit button on the viewer bar opens edit mode on the chosen checkpoint, whether it is an import or a design of yours (for a design, its already rendered mesh is frozen; the colors of a multicolor checkpoint are lost in that base, and you recolor per piece). The preview is immediate.

  • Move, Rotate and Scale (W, E, R): drag the gizmo's arrows or rings or type the values in mm and degrees in Properties. The center cube of Scale scales evenly; the arrows scale per axis. The gizmo works on the center of the model's box, not on the file's origin (which in an STL is often far from the part).
  • Step snapping (the magnet): 1 mm, 15° and 0.1 by default; change them in Properties.
  • Live measures: the box of the selection and of the whole set, and the height of the lowest point.
  • Mirror on X, Y or Z (along the file's axes; the center of the box does not move), Center on the plate, Rest on the plate (the lowest point goes to Z = 0) and Face: click a face of the model and it turns until that face lies against the plate.
  • Color of the model and of every piece you add.

Cut with a plane

The Cut button creates a plane through the center of the model, with its own gizmo to move and tilt it (or with the point and the normal typed in, with Horizontal, Vertical X and Vertical Y shortcuts). The plane's arrow marks the "above" side. You choose what stays: the upper part, the lower part or Split in two, and then the two halves as objects apart in X (to print them separately) or as colors in place (for a multicolor 3MF), with a color picker per half.

Cube, cylinder, sphere and text: addition or hole

With Addition or Hole chosen, the cube, cylinder, sphere and text buttons add a piece at the center of the model. Each one has its gizmo, its size (X·Y·Z, diameter and height, letter size and extrusion), its color and its mode, which you can change afterwards. A hole is subtracted from everything it touches and is shown in the view as a translucent red volume: it is a preview; the real result is the render when you apply.

The operation stack and undo

Everything you do lands on the stack with a readable label ("Move the model to (−24, −62, 0) mm", "Add Cylinder 1 as a hole"…): those labels go as comments in the checkpoint code. Several consecutive moves of the same object merge into one. ⌘Z and ⇧⌘Z (Ctrl+Z and Ctrl+Shift+Z on Windows) undo and redo, and a click on a step goes back to it; struck-through steps can be redone. The shortcuts only act with focus inside Edit mode, so they do not clash with the code editor's.

View code, Apply and Discard

View code shows the OpenSCAD that would be saved, writing nothing. Apply asks for an optional label and creates the new checkpoint, a child of the one you were editing, and selects it so it renders. Discard (or Esc) leaves without keeping anything, with a confirmation if you have made changes; changing checkpoint or closing the project with an edit half-done asks too. Edit mode is not remembered when you close the app.

Open meshes

A mesh that is not closed can be moved, rotated, scaled and mirrored, but cutting or drilling it fails in OpenSCAD ("mesh is not closed"). The viewer shows a notice while you edit and, if the edit cuts or drills, ScadLab asks before applying. The simplest fix is to repair the mesh before bringing it in.

Modify with AI

In a checkpoint's menu (right-click) and on the Edit-mode bar, Modify with AI opens the chat with the model already attached —with its report and preview— and "Modify this model: " typed in the message box, for you to finish the sentence. Whichever provider you have chosen answers, Hermes or a CLI, using the import_mesh tool and the openscad-stl-editing skill. What you have not applied in Edit mode does not travel: the model is attached as it is saved.

In a narrow panel

The toolbar becomes icon-only and wraps onto several lines, the side panel turns into a drawer with tabs (Properties and Stack) under the viewer and the measures shrink to that of the selection: nothing is cut off and there is no horizontal scrolling.

The code editor Available

Monaco —VS Code's editor, bundled in the app, no internet needed— with OpenSCAD highlighting, find and replace, automatic formatting, autocomplete with each module's documentation and a linter that checks the code as you type. Saving never touches the checkpoint: it creates a new one.

Read-only and edit mode

A checkpoint is immutable, so the code opens read-only (the padlock in the panel header and in the status bar says so). Click Edit or double-click the code to switch to editing. While you edit, the tree does not change: the checkpoint remains what it was until you save. Discard (the curved arrow) goes back to the saved code; if you switch checkpoint or workspace with unsaved changes, ScadLab asks before losing them.

Save = new checkpoint

⌘S / Ctrl+S (or Save) opens a short dialog: the label gives the file name (007-lid-screws.scad; ScadLab assigns the number) and the description goes into the @checkpoint header. The new file is a child of the one you were viewing, appears in the tree, opens and —with auto-render on— renders on its own. Just as if the AI had done it.

Autocomplete and help for each module

As you type, OpenSCAD's modules, functions, keywords and special variables ($fn, $fa…) appear with their signature and an explanation in your language. Choosing one opens the parenthesis with the first parameter highlighted, and the signature help shows the rest while you type the arguments (named ones too: r = 3 highlights r). Hovering over a built-in module shows the same help.

Find and replace

  • ⌘F / Ctrl+F — find (also in read-only), with match case, whole word and regular expressions.
  • ⌥⌘F or ⌘H / Ctrl+H — find and replace (in edit mode).
  • Enter / Shift+Enter — next / previous; Esc closes.

Format

The wand button, ⇧⌥F / Shift+Alt+F or the context menu tidy up the code: indentation by braces and parentheses, one space around = and operators, no trailing spaces or extra blank lines. It is conservative: it never joins or splits lines, does not touch the inside of strings or comments and respects the alignment of the // [min:step:max] annotations. A single ⌘Z undoes it. In read-only, formatting switches to editing first. The indentation (2 or 4 spaces) is chosen in Settings → General → Code editor.

The group's ⋯ menu and each tab's right-click have Move to…, with destinations that always work, no dragging. It works for any panel —3D viewport, Source, Agent 1, Agent 2, Chat and Problems— and moving destroys nothing: it only changes place; the viewer keeps its camera, the editor its text and the terminal its agent.

  • Next to…: lists the other panels in view; the one you choose gets the panel as a tab of its group.
  • Float / Dock: takes the panel out to a floating window or puts it back in the grid.

Minimize a panel

  • A group side by side with another becomes a narrow strip with its tabs' icons vertically (a green or orange dot stays in view if an agent is running or there are unsaved changes).
  • A floating group shrinks to its tab bar.

The other panels share the freed space. To restore: a click on any tab or icon of the group, the + button (Restore panel) or a double-click on the empty part of its bar; it goes back exactly to its previous size. Panel sizes

Every edge between two groups is a divider you drag in both directions: the line is 1 px, but the grab zone is about 6 px and the cursor changes when you hover over it. Double-clicking a divider splits the space equally between its two sides.

  • No panel can be left unusable: the viewer does not go below about 200 × 150 px, the code and the terminals about 240 × 120 px (these sizes grow with the interface size).
  • Sizes are saved with the layout, also in named layouts.
  • If you shrink the window, the groups share the space proportionally instead of overflowing it.

Floating panels

Float (right-click the tab) takes the panel out to a window that lives inside ScadLab, on top of the others. You move it by dragging its tab bar and resize it from any edge or corner, and it cannot leave the window. Dock puts it back in the grid. A floating group can carry several tabs.

Workspace rules: CLAUDE.md and AGENTS.md

Each workspace carries a rules file that the agent reads on start. It is what guarantees the history does not break, whichever agent you use.

Which file each agent reads

  • CLAUDE.md — Claude Code.
  • AGENTS.md — opencode, Codex and Antigravity.

The mandatory rules

  1. Never overwrite or delete a .scad: each change is a new checkpoint.
  2. Use colors: every top-level part inside color(...).
  3. Validate each checkpoint with the tools of the ScadLab MCP server (or with OpenSCAD on the command line if they are not available) before calling it done.
  4. Parameters at the top, with Customizer comments; everything in millimeters.
  5. Respect printer.json: the model has to fit on the plate.
Tip

You can add your own rules at the end of the file —“always use 4.2 mm M3 inserts”, “no overhangs greater than 45°”—, but do not remove the mandatory ones: they are what keeps the checkpoint tree coherent.

Your notes are not overwritten

ScadLab's rules go inside a marked block in CLAUDE.md and AGENTS.md (between <!-- scadlab:rules:begin --> and <!-- scadlab:rules:end -->). Every time you open the workspace, ScadLab updates only that block with the current version's rules (for example, the MCP tools or the branches): whatever you write before or after the block stays as it is.

  • If the file was created by an earlier version of ScadLab (no markers), a copy is saved in .scadlab/backup/ before replacing it, in case you had edited it.
  • If you import a folder that already had its own CLAUDE.md, the block is added at the top and your instructions stay below, intact.

The ScadLab MCP server

An MCP server that gives the agent tools to render, validate, measure and see its models with the same OpenSCAD and the same engine the app uses. ScadLab leaves it configured automatically in each workspace for Claude Code and opencode, and passes it to Codex through flags; Antigravity only has a global configuration, so it is added with a button and your permission. From this version the AI can do with its tools everything you do with the interface —change measures, create from templates, edit an STL, estimate and orient the print, install libraries and use the trash—: see the full list.

What it is and what it is for

MCP (Model Context Protocol) is the standard way to give tools to an AI agent. ScadLab's server is the program itself launched as ScadLab --mcp --workspace <folder>: it opens no window, works on the workspace's files and works even with the app closed (for example, with an agent launched from an external terminal).

Without it, the agent has to guess whether its code compiles and how the part came out. With it, it checks before telling you it is done: it renders, reads the diagnostics with their line, measures the part, looks at how it looks and exports it.

How it is configured in each CLI

When you create, import or open a workspace, ScadLab writes the scadlab entry in the project configuration file each CLI reads. It never touches your user's global configuration on its own; the only exception is Antigravity, which only reads global configuration, and only when you pick it in the chat or open its terminal (see below).

Heads up

.gemini/settings.json is the file of the legacy Gemini CLI (gemini), the one Antigravity replaced. Antigravity (agy) does not read it: we checked with agy mcp list, which with that file in the project still says “No MCP servers configured”. ScadLab keeps writing it for anyone who still uses gemini, but for Antigravity the button is needed.

In all of them the command is the same: ScadLab's executable with --mcp --workspace and the workspace folder. If you move or update the app, the executable's path changes: ScadLab fixes it the next time you open the workspace.

What ScadLab respects in your files

  • It merges only the scadlab key: the rest of the file —your other servers, your settings, the order and the indentation— stays exactly as it was. If you added your own fields to the entry (a timeout, for example), they are kept.
  • If the file is not valid JSON (or the block is not an object), it does not touch it: it marks it as “Left alone” in Settings → AI so you can fix it.
  • If your project has an opencode.jsonc with comments and no opencode.json, it does not touch it either (editing it would delete your comments): add the entry by hand with the command shown in Settings → AI.
  • Syncing several times changes nothing if it was already up to date: the file is not rewritten.

Codex: through flags when opened from ScadLab

Codex does not read project configuration. That is why, when you open it in ScadLab's terminal, the app adds to it at launch two -c flags with the server's command (mcp_servers.scadlab.command and mcp_servers.scadlab.args). It only applies to the Codex you open from ScadLab; if you launch it yourself in another terminal, it will not see the server.

Antigravity: global configuration, added when you pick it

Antigravity does not read project configuration or accept being handed a server at launch: its only MCP server configuration is global (the ~/.gemini folder) and is managed with the agy mcp command. And without the server it has none of ScadLab's tools: it tries the shell, which is denied, and the turn leaves nothing. That is why, when you pick Antigravity in the chat or open its terminal, if agy mcp list does not list scadlab, ScadLab registers it on its own with agy mcp add -- scadlab <ScadLab> --mcp and tells you with a message that it added it to its global configuration. It only adds what is missing: an entry that already exists —even if it points to another path or is disabled— is your decision and is left alone. With the MCP server turned off in Settings → AI it does nothing. If agy does not let it add it, the error says why and the chat explains that without that server Antigravity cannot create checkpoints; you can still ask it for the design in a block and ScadLab saves it with the automatic save. In Settings → AI → ScadLab MCP server there is an Antigravity row with its state and two buttons to do it by hand:

  • Add to Antigravity: before doing anything it warns you that it will modify Antigravity's global configuration, that is, that of all your projects and not just this workspace. If you accept, it runs agy mcp add with ScadLab's executable and --mcp. If a scadlab server with another path already existed (because you moved the app), it replaces it; your other servers are not touched.
  • Remove from Antigravity: likewise, with confirmation; it runs agy mcp remove scadlab.

The state can be agy not installed, Not configured, Configured, Other path (the app moved: “Add” fixes it), Disabled or Could not read; it comes from agy mcp list.

The global entry is scadlab → <ScadLab> --mcp, without --workspace: the server uses the folder it is launched from, and Antigravity launches it in the project folder, so a single entry serves all your workspaces. That is the delicate point: if in your version of Antigravity the server were not launched inside the project folder, the tool will tell you when you use it (that folder would not be a workspace). As a safeguard, in every chat turn ScadLab puts the project folder in the SCADLAB_WORKSPACE variable, which the server uses if it has no --workspace (and its first line in the log says which one it used). If it still works in another folder, remove the entry from here and add it by hand with --workspace.

Antigravity in the chat: approving ScadLab's tools

Registering the server is not enough. When ScadLab runs Antigravity from the chat (agy --print) nobody can answer a permission prompt, so Antigravity refuses the first tool it was not pre-approved for —“permission check failed for mcp scadlab/…”— and ends the turn right there: the chat used to say it “finished the turn without saying anything”. To avoid it, ScadLab adds to Antigravity's own settings file, ~/.gemini/antigravity-cli/settings.json, one rule per ScadLab tool under permissions.allow, in the exact format Antigravity asks for: mcp(scadlab/list_checkpoints), mcp(scadlab/create_checkpoint)… It is an explicit list of ScadLab's own tools —the reading ones and the ones that create or change the project—: never a wildcard, never command(…). It does it the first time you use Antigravity in the chat, next to registering the server, and a notice tells you what it added and where; from then on it keeps the list in sync on every turn (it adds the tools that are new and removes the ones that no longer exist). Everything else in the file —trustedWorkspaces, your own rules, the order of the keys— stays as it was; a copy of the file is saved first in ScadLab's data folder, and if the file is not valid JSON it is not touched (the chat tells you).

“Query only” keeps working. The rules are global —the same in Agent and in Query only—, so ScadLab's own server enforces the mode: during a Query-only turn the chat leaves a mark in the project (.scadlab/turn-mode, removed when the turn ends, with an expiry so it is never left behind) and the server refuses the tools that change the project with the reason, so Antigravity hands you the design in a block. In Agent mode everything goes through. The shell stays denied and --dangerously-skip-permissions is never used.

They are global

The rules apply to every use of Antigravity, also when you open it yourself (in ScadLab's terminal or anywhere else): its permission prompts will not ask for ScadLab's tools, the ones that write included. If you prefer to approve them one by one, remove them as explained next.

See, remove or repair the permissions

In Settings → AI providers → Detected CLIs, Antigravity shows “ScadLab permissions: N tools approved” with two buttons. Remove deletes only the mcp(scadlab/…) rules (after asking, and saving a copy of the file first); it is a decision ScadLab respects: it does not add them back by itself. Add back puts them again and restores the automatic sync. If Antigravity blocks a ScadLab tool anyway —you removed the permissions, the file was not valid JSON, one of your own rules asks first—, the chat message names the tool, the file and the step to follow, and a notice offers Repair Antigravity permissions, which syncs the list again.

Claude Code: no approval when opened from ScadLab

A server that comes in the project's .mcp.json stays pending approval until Claude Code asks you, the first time, whether you trust it (we checked it with claude mcp list: “Pending approval”). So as not to hold you up, when you open Claude Code in ScadLab's terminal the app passes it the server with --mcp-config, which does not need that approval. If you open it yourself in another terminal, the .mcp.json is used and Claude asks you once.

Turning it on, off and syncing

In Settings → AI → ScadLab MCP server:

  • The switch turns it on or off for all workspaces. Off, ScadLab removes its entry from the files (and deletes the file if it only existed because of it) and stops passing the flags to Codex. It is on by default.
  • The command the agents run can be copied, in case you want to configure a CLI ScadLab does not know.
  • For the open workspace you see the state of each file: Configured, Missing, Out of date (the app moved) or Left alone. Sync again repeats the write without waiting for you to open the workspace.
  • The Antigravity row is separate because its configuration is global: it is added or removed with its buttons, see Antigravity. The switch and “Sync again” do not touch it.

If ScadLab cannot find OpenSCAD, the block says so: render, preview and export do not work until you install it or set its path in the OpenSCAD tab.

The “MCP ✓” indicator

On each agent panel's bar, to the left of auto-iteration, MCP ✓ says the server is configured in this workspace. It changes to MCP ! (in amber) if some file was not left up to date and to MCP off if you turned it off. A click opens Settings → AI with the details.

How to check that an agent sees it

  1. Open a regular terminal in the workspace folder.
  2. For Claude Code, run claude mcp list: scadlab shows up as Connected or, if you have not approved it yet, as Pending approval (it is approved the first time you open claude in that folder). Inside a session, the /mcp command shows the real status.
  3. For opencode, run opencode debug config and look for scadlab inside mcp. Its opencode mcp list only lists servers inside a git repository: in a workspace that is not a repository it may say there are none even though the session does use it.
  4. For Antigravity, run agy mcp list in any folder: scadlab must show up as enabled with ScadLab's path and --mcp. Looking at the workspace is no use: agy does not read .gemini/settings.json.
  5. For Codex, open it from ScadLab's terminal and ask it to use the render tool (or to list its tools): outside ScadLab it does not receive the server.

If a CLI does not see it

  • Claude Code asks you to approve the server. That is normal: the first time it opens a project with a .mcp.json it asks whether you trust it. Accept.
  • The file shows up as “Left alone”. It has broken JSON or a format ScadLab does not dare edit. Fix it (or add the entry by hand with the command shown in Settings → AI) and click Sync again.
  • It shows up as “Out of date”. You moved or updated the app and the path changed: click Sync again.
  • You opened the CLI with the app closed. It works all the same (the server is the app itself launched without a window), but the path the file names has to still exist.
  • Codex does not see it. Open it from ScadLab's terminal: only there does it receive the flags.
  • Antigravity does not see it. ScadLab adds it by itself when you pick it in the chat; if it could not, or you removed it, click Add to Antigravity in Settings → AI: the workspace file is not enough. If it says agy not installed, install Antigravity or check that the agy command exists on your machine.
  • Antigravity “blocked ScadLab's tool” in the chat. The permission rules of ScadLab's tools are missing from its settings file (you removed them, the file was not valid JSON, or one of your rules asks first): click Repair Antigravity permissions in the notice, or Add back in Settings → AI providers (see approving ScadLab's tools). If the message also says Antigravity does not trust the folder, open it once with Antigravity and accept “Yes, I trust this folder”.
  • The tools fail when rendering. Check that ScadLab finds OpenSCAD (the OpenSCAD tab of settings).

Auto-iteration on errors

If a checkpoint does not render, ScadLab tells the agent and asks it to fix it — without you having to copy the error.

What it does

When an agent creates a checkpoint, ScadLab renders it on its own and, if it fails, leaves RENDER_ERRORS.md in the workspace. If there is also an open agent in that workspace, it writes a notice in its terminal for it to read and fix. Details of the file in Rendering and diagnostics.

How it works

  1. The agent creates 004-add-hinge.scad and ScadLab renders it.
  2. OpenSCAD fails. ScadLab writes RENDER_ERRORS.md in the workspace with the file, the line and the message.
  3. ScadLab writes in the agent's terminal a one-line notice asking it to read RENDER_ERRORS.md and fix it.
  4. The agent creates 005-fix-hinge.scad with parent=004-…. 004 stays as it was.
# RENDER_ERRORS.md
File: 004-add-hinge.scad
ERROR: Parser error in file 004-add-hinge.scad, line 31: syntax error
Fix the error in a NEW checkpoint with parent=004-add-hinge.scad.

The notice the agent sees always starts with “ScadLab:”, so that no CLI mistakes it for a command:

ScadLab: the render of "004-add-hinge.scad" failed with 1 error. Read RENDER_ERRORS.md and fix it in a NEW checkpoint with parent=004-add-hinge.scad; do not edit the file that failed.
Why a new checkpoint

Fixing in place would break the immutability rule and you would lose track of what the AI tried. That way the tree also shows the stumbles.

When it notifies and when it does not

  • It only notifies when the render of the newest checkpoint fails. Rendering an old one while you browse the history sends nothing to the agent.
  • It notifies once per failure: if the same error repeats, it does not insist.
  • After 5 notices in a row without a successful render, it stops notifying so as not to burn your agent's quota in a loop. It works again as soon as a render succeeds.
  • A cancelled render, or one without OpenSCAD installed, does not count as a model failure and does not notify.
  • With no agent open in that workspace, there is nobody to notify: RENDER_ERRORS.md stays for when you open one.

The Auto-iterate switch, on the terminal bar, turns it on or off (it is on by default). Off, the agent gets no notices; RENDER_ERRORS.md is still written.

Hermes: the chat with tools and AI providers

The Chat tab talks with the provider of your choice —an AI CLI you already have installed (Claude Code, Codex, Antigravity, OpenCode) or a model server, local or in the cloud— and, in Agent mode, that provider uses ScadLab's own tools: it creates a checkpoint, renders it, looks at it, measures it and fixes it by itself until the part is what you asked for. With a model server, that agent is called Hermes.

Chat or terminal

The chat works inside ScadLab: it creates checkpoints, renders and measures without you copying anything, and the conversation is saved per project. The agent in the terminal (Claude Code, opencode, Codex, Antigravity) is still the way to get the full experience of a CLI; both use the same tools.

Your CLIs: detected on their own

Claude Code, Codex, Antigravity and OpenCode show up by themselves in the picker if you have them installed: there is nothing to configure and no path to type. ScadLab looks for them in the PATH, in the usual locations and, on macOS, in your login shell's PATH (a graphical app does not inherit the terminal's). One that is not installed does not show up, and one you just installed appears when you open the picker, without restarting. Each CLI runs in the workspace folder with the ScadLab tools connected, and its steps reach the chat with the same cards Hermes uses; the conversation resumes with the CLI's own session.

  • Status dot over each icon: green means it responds (a CLI, that it is installed; a server, that it answers), red means it does not. Next to the picker, a latency pill (18 ms) for servers, refreshed by itself every minute, when you switch provider and with a click; if the server goes down, a notice above the box says so and lets you retry.
  • It works from the keyboard: ↑ ↓ move, Enter picks and Esc closes.
  • Add an AI provider… opens Settings → AI providers, where you also see the detected CLIs with their version.

AI providers: servers and keys

In Settings → AI providers you add the servers the chat can talk to, several of each kind. Add server offers shortcuts that already bring the address: Ollama (local and remote), LM Studio, llama.cpp, vLLM, OpenAI, OpenRouter, Google Gemini, Anthropic, Groq, DeepSeek, Mistral, Together, xAI or any OpenAI-compatible server.

  • Test connection tells you, before saving, whether the server answers (and how many models it has) or why it does not: refused connection, timeout, wrong key (401).
  • The API key is stored encrypted (AES-256-GCM) in the settings database, with a key derived from your master password, never in plain text, and it is never shown again or leaves your machine except toward the server you chose. Leave the field empty when editing to keep the saved key.
  • If you prefer not to save it, type the name of an environment variable that holds the key; ScadLab reads it from there (also if you defined it in ~/.zshrc), with no password at all.
  • The servers you already had from earlier versions are kept, and your old chats still open.

Import your mini-tools servers

If you already have servers in mini-tools, Import servers from mini-tools (next to Add server) brings them in three steps: it shows the list, asks for confirmation and only then copies them —name, type, address and default model—. The ones that already exist in ScadLab (same name or same address) are skipped. ScadLab only reads those fields and never opens anything encrypted: keys are not copied, so each server arrives without a key and you type it again. If mini-tools is not on your computer, the dialog says so and does nothing.

Master password: the key vault

The first time you save an API key, ScadLab asks you to create a master password. It is what encrypts your keys on this computer (AES-256-GCM, with a key derived from the password using Argon2id); the password itself is never stored. You create it just once.

  • Remember on this device comes checked. ScadLab keeps the derived key —never the password— in the system keychain (Keychain on macOS, Credential Manager on Windows) and from then on uses your keys with no questions: saving another key, chatting or opening the app never asks again. The key is read from the keychain once per session, the first time something needs it.
  • If you uncheck it, or the system keychain denies access, ScadLab asks for the password once per session, and only when something needs a key: sending a message to a server that has one, listing its models or testing the connection. After you type it, the action you were doing goes on by itself.
  • In Settings → AI providers → Key vault you can change the password (every key is encrypted again, all or nothing), Forget this device (deletes the key from the system keychain) or Reset.
  • If macOS ever asks whether ScadLab may use the keychain, Always Allow avoids the question; if you deny it, nothing breaks: ScadLab just asks for the password once per session.
  • The environment-variable alternative above needs no password at all.
No way back

A forgotten master password cannot be recovered. The only way out is Reset, which deletes every saved API key and the password (the servers stay, without a key); then you type the keys again and create a new password.

Starting a chat and choosing the model

  1. Open the Chat tab and click New chat. You see the provider, the model and the mode you are going to talk to, and four suggestions (a snap-fit box with a lid for a Raspberry Pi 5, copy the part in this photo…): a click fills the message box and you edit it before sending. Above them, Create from an image opens the dialog to model from photos.
  2. Pick the provider and then the model: the list comes from the provider, with a search box. On a server, each model shows whether it sees images and whether it uses tools —when the server reports it—, its context window and, with providers that publish prices (OpenRouter), what it costs per million tokens. The Vision only button shows only the models that see images. If the provider does not list it, type the name by hand.
  3. Type what you want and send with Enter (Shift+Enter adds a line; ⌘/Ctrl+Enter also sends).

You can change provider and model in the middle of a conversation: the history is kept and the next message already uses the new one. ScadLab remembers the last one you picked in each project.

The chat bar and narrow panels

The top bar always fits on one line: the conversation title (click it to rename), the provider with its latency, the model, the workspace and the mode. When the panel shrinks, the secondary things fold: first the workspace chip and New chat move to the “…” menu; then the latency is hidden (the provider keeps its status dot) and the mode becomes just an icon; and in a very narrow panel the provider and the model become icons with their description on hover and the mode moves to the menu too. There is no horizontal scroll or cut-off control from about 320 px up to a full window, and the dropdowns never leave the window.

  • Message box. The shortcuts are shown under the box: Enter sends, Shift+Enter adds a line and ⌘/Ctrl+Enter also sends. Pending attachments show above the box and Stop shows a clock.
  • Context counter. Next to the shortcuts, the estimated tokens of the draft plus the conversation (4 characters ≈ 1 token) against the model's window, when the provider reports it; it turns amber at 70 % and red at 90 %, and it is the cue to start a new chat. It does not count the system instructions or the attachments.

The modes: Ask only and Agent

The mode is picked in the bar (and under the box you read what it allows). Every new chat starts in Agent, with any provider: asking for a part has to end in a .scad that is created, rendered and visible in the viewer, and that only happens if the provider can create. Ask only is your choice and it belongs to that conversation: the other chats stay as they were and the next new chat starts in Agent again, even if you left another one in Ask only. The mode is saved with the conversation, so it is still there when you reopen it (the Switch to Agent notice saves it there too).

The terminal has no mode. The CLIs you open from the ScadLab terminal (Claude Code, Codex, Antigravity, OpenCode) are not restricted by ScadLab: they get the ScadLab server, the folders of your other open projects and the session you resume, and nothing that puts them in plan or read-only mode, or that skips permissions —there you approve in your own terminal—. The same goes for ScadLab --mcp: it offers the writing tools by default.

In neither chat mode does a CLI run shell commands or get permission to skip its own checks. In Agent mode, the model decides what to do: it looks at the checkpoints and the printer, creates a checkpoint with complete code, renders it, looks at it from a view, measures it and, if something fails, fixes it in another checkpoint (it never edits an existing one). It can also read the workspace skills and inspect the references you attach. The checkpoints it creates show up in the tree like any other.

  • Each step is a card with the tool and its status. Without opening it you see the checkpoint it refers to —a link that selects it in the tree and opens it in the editor and the viewer—, the mesh data of a render or a measurement (size, triangles, whether it is closed, whether it fits the plate) and, if it fails, the line and the offending code. The picture the model looked at is shown in the card and can be enlarged with a click; a click on the card unfolds the arguments and the raw response.
  • The model sees what it draws if it has vision; otherwise it only gets the measurements and ScadLab warns you.
  • Steps (with a server): the limit of tool calls per message (1 to 30, 12 by default). When it is reached, the model summarizes what it achieved and stops; ask it to continue if something is missing.
  • Stop shows a clock and cuts at once, even in the middle of a tool: what was already done is kept.
  • If the model does not use tools, “Agent” turns itself off and explains why; if the server rejects them on the first try, the chat continues as plain text with a notice (and ScadLab saves the code it writes for it: see below).

It always ends in a part

In Agent mode the request of someone who does not know OpenSCAD has a single possible ending: a .scad that is created, rendered and visible. The provider follows the flow create checkpoint → render → look → fix in a new one, and in a workspace with no checkpoint at all it creates the first one without asking (it becomes the root of the tree, with no parent). Every checkpoint born in the chat —from a tool, from the automatic save or from a button— is selected on its own in the tree, in Code and in the viewer, and rendered, even if you have auto-render off. If you are in the middle of an unsaved change in the editor, ScadLab does not switch your file: the checkpoint shows up in the tree and in the step card.

If the model answers with code: it is saved for you

Some models cannot call tools (a small local model, for example) and some CLIs never got the MCP server: they answer with the design in a block and nothing else. In Agent mode, if the turn ends without having created any checkpoint and its text carries a complete OpenSCAD block —the design one: the last complete block, if there are several—, ScadLab saves it for you: as the root if the workspace is empty and, if not, as a child of the open file (or of the active parent), with its @checkpoint header. It renders it and shows it as one more step, “Saved automatically”, with the link to the checkpoint. If the provider already created one with a tool, or wrote the .scad on its own, no duplicate is saved.

With a model server there is also a fallback loop: if the render fails and steps are left (the Steps limit), the model receives the errors with their line and sends the fixed block, which is saved as a child of the one that failed. With a CLI it is a single attempt: the render card shows the error with its line and you ask for the fix in the next message.

Code in the answers: save it or open it

Each OpenSCAD block comes with Copy and, once it has finished arriving, ways of bringing it into the project (in a narrow panel the buttons become icons with their description):

  • Create checkpoint and render (in Ask only, highlighted): saves the code as a checkpoint without asking (the name comes from the block's header), selects it in the tree, in Code and in the viewer, and renders it. In a workspace with no checkpoint at all it is the root: you no longer have to ask an agent for “the first one” beforehand.
  • Save as checkpoint opens the dialog to name it and creates it as a child of the open file or, if none is open, of the latest checkpoint (or as the root, if the workspace is empty).
  • Open in editor (in Agent) does the same as creating without asking, selects the new checkpoint and shows the Code panel. Checkpoints are not edited and the editor always shows one, so “opening” a block means saving it and opening it. If the turn already created a checkpoint, the blocks that repeat the code do not offer to save it again.

Switch to Agent. If in Ask only what you type (or what you last sent) asks to create or change a part, a notice shows up above the box that says so and lets you switch to Agent with one click; the X hides it for that message.

Long blocks start folded. Links in an answer open in your system browser.

Create a model from an image

Give ScadLab one or several photos of an object —or a sketch with measurements— and the AI models it in OpenSCAD: it works out what the object is and its scale, builds it from simple shapes, renders it and compares the result with your photo until it matches. It follows the included skill openscad-from-image, and works with the chat of any provider.

The “Create from an image” dialog

The Create from an image button is in the empty chat and, in a project with no model yet, next to Create a starter model in the viewer and in Code. It asks for three things:

  • Photos: one or several (up to 10), choosing them, pasting them (⌘V / Ctrl+V) or dragging them onto the box. Front, side and top views of the same object help a lot.
  • Reference measurement (optional): “the total width is 80 mm”, “there is a coin next to the part”, “the hole is 6 mm”.
  • What is it? (optional): “a wall mount for headphones”. It helps decide how to model it.

Create model opens a new conversation in Agent mode, attaches the photos, writes a structured message —the object, the reference and a pointer to the skill— and sends it. Closing the dialog with Cancel discards the photos you had chosen.

Each photo you send is also copied into the project, in refs/images/ (named after the photo plus a short code of its content, so the same photo sent twice is a single file and nothing is overwritten): that is where the image tools read it, and it is not lost between messages or between providers.

Scale: the measurement that matters most

A photo does not say how big things are. Give one real measurement, or leave a known object next to the part: a coin, a credit card (85.60 × 53.98 mm), an A4 sheet. The assistant looks it up in the skill's table, scales everything from it and tells you which measurement it used. If it has none, it estimates the scale and says what it assumed, so you can correct it.

Photos that work best

  • Straight on (not at an angle), with the object filling the frame and a plain background that contrasts with it.
  • Even light, no strong shadows.
  • A second photo from the side (and another from above) gives it the depth a single photo cannot.
  • A hand-drawn sketch with its dimensions works too: the assistant reads the numbers.

It checks its work against your photo

After rendering, the assistant calls compare_with_image: it picks the view of the model that looks most like your photo and puts both side by side (or draws the model's silhouette over the photo). The step card shows that image large and three data points:

  • the view it compared from;
  • the width/height proportion of the model and of the object in the photo: if they are close, the proportions match;
  • the IoU: how much the two silhouettes overlap, 100 % being identical. Green from 85 %, amber below 60 %.

With that, it corrects what differs in a new checkpoint (checkpoints are never edited) and compares again.

Flat outlines, logos and reliefs

A plate with a logo, a stamp or a silhouette is not “modeled”: it is traced. trace_image_outline finds the outline, removes specks, simplifies it and writes an SVG in millimeters to refs/ (one per color if you ask for layers); the model then does linear_extrude(h) import("refs/logo.svg"). The card shows the traced silhouette and the files it created. image_to_heightmap turns a photo into a relief or lithophane (surface()), and image_info zooms into a region of the photo and enhances it to read a dimension.

If the model does not see images

If the model you chose said it cannot see images, a notice appears above the box with two ways out:

  • Switch to a model with vision opens the model list filtered to the ones that see images (the Vision only button turns the filter off).
  • Use outline tracing sends it anyway: the photo is not shown to the model, it stays in refs/images/ and the model is asked to use trace_image_outline, which needs no vision. It is enough for silhouettes and logos; for a part with relief, pick a model with vision.

What to expect

  • Mechanical parts, enclosures, mounts and plates come out well; organic shapes (figurines, faces) are approximated with simple shapes and the assistant says so.
  • A photo is not a scan: there is no depth. The more views and measurements you give, the closer it gets.
  • An image can weigh up to 20 MB in the chat: if it is larger than 2048 px or 5 MB, the model gets a scaled-down copy and refs/images/ keeps the original for the tools. The processing (outline, comparison, relief) is done by ScadLab on your computer; the photos reach the model only if it sees images.

The first time you export a multicolor model, it is worth doing this check by hand:

  1. Open the file in Bambu Studio (with Open in Bambu Studio or with File → Import or by dragging it into the window).
  2. If it asks whether to load it as one object with several parts, answer yes.
  3. Check the object list: you should see one object with a part per color, each part with its extruder (1, 2…) and its color's name.

You set the filament colors

The 3MF carries each part's color as a reference, but you choose the real filament in Bambu Studio's AMS.

Multicolor with the AMS

One part per color in OpenSCAD, a 3MF with those parts, and in Bambu Studio each part goes to a filament in the AMS or AMS lite.

The rule: one part per color

Each top-level block goes inside its own color(), and the parts must not overlap: where two colors occupy the same volume, the slicer does not know which to use. Subtract one from the other if they touch:

// @checkpoint parent= desc="Two-color nameplate"
/* [Plate] */
w = 80; d = 25; h = 3;
txt = "LUCIA";
relief = 1;

module label() {
  translate([w/2, d/2, h - relief])
    linear_extrude(relief) text(txt, size = 11, halign = "center", valign = "center");
}

color("White") difference() { cube([w, d, h]); label(); }   // base with the recess
color("Black") label();                                    // text that fills the recess

Here the text is inlaid in the base (same total height): it comes out flat and prints with no height changes between colors.

Export Available

How many colors

AMS lite (A1, A1 mini): 4. AMS: 4 per unit, up to 16 by chaining units. Every color change purges filament: fewer colors and fewer layers with a change is faster and wastes less.

How it is calculated (simply)

A part is not printed solid: the walls are printed fully and the inside only in part (the infill). The calculation, for each part:

  1. Wall = perimeters × line width (by default 2 × 0.42 mm = 0.84 mm thick).
  2. Shell = the part's surface × wall thickness. It is the walls' material, printed solid. If the part is so thin that the wall takes more than its volume, only the volume counts (no extra material is counted).
  3. Interior = volume − shell, and only the infill % of it is printed.
  4. Effective volume = shell + interior × infill.
  5. Weight = effective volume × the material's density.
  6. Filament = effective volume ÷ the filament's cross-section area (by default 1.75 mm diameter).
  7. Cost = weight ÷ 1000 × the material's cost per kg.

Example

A 20 mm cube: volume 8000 mm³ and surface 2400 mm². With the 0.84 mm wall, the shell is 2400 × 0.84 = 2016 mm³ and the interior, 8000 − 2016 = 5984 mm³. With 15 % infill, the effective volume is 2016 + 5984 × 0.15 = 2913.6 mm³. In PLA (1.24 g/cm³) it weighs 2.9136 × 1.24 ≈ 3.61 g, takes about 1.21 m of 1.75 mm filament and, with PLA at 20 of currency per kg, costs ≈ 0.07.

Branching a design to try two variants Available

You have a box that works and you want to try two different lids without losing either.

  1. Start from the good checkpoint, for example 003-base-box-final.scad.
  2. Right-click it and choose Branch from here: it is marked as the active parent.
  3. Ask for the first variant:

    Add a snap-fit lid with a 2 mm lip and 0.2 mm clearance.

    004-snap-lid.scad is created (parent=003) and becomes the active parent: the tree advances on its own.
  4. Go back to 003: right-click → Branch from here. This is the step that opens the second branch; without it, the next request would keep hanging from 004.
  5. Ask for the second:

    Starting from this checkpoint, add a screw-on lid with four M3 screws at the corners.

    005-screw-lid.scad is created, also with parent=003: the tree shows two branches.
  6. Compare them with the split view or by looking at each lid's weight, or use Compare with parent to see what changed in each.
  7. Export the winner. The other stays in the tree in case you change your mind; if you no longer want it, send it to the trash (with its branch, if it has children): it can be restored.

FAQ

Do I need to know OpenSCAD?

Not to get started: you describe the part and the AI writes the code. Being able to read it helps you ask for precise changes (“raise wall to 2.4”), and the editor lets you tweak it by hand.

Do I need an AI subscription?

For the terminal agents, whatever each CLI requires (Claude Code, Codex…); for the chat, that of its provider. If you do not want to pay, use the chat with Ollama locally, with less accuracy.

Why can't the AI edit a checkpoint?

Because the history is rebuilt from the files: if one changed, the tree would stop telling the truth. See why they are immutable.

Which printers does it work with?

The catalog has seven brands (Bambu Lab, Prusa, Creality, Elegoo, Anycubic, Snapmaker and UltiMaker) with their datasheet, skill and slicer; see Printers and workspace settings. If yours is not there, pick the closest one: the STL works for any slicer and the FDM rules are the same.

My printer is a Prusa with an MMU3: which format do I export?

Pick 3MF for PrusaSlicer in the export dialog (it comes preselected when the printer's slicer is PrusaSlicer). With UltiMaker Cura use one STL per color.

I exported to 3MF and the slicer does not show the colors

Check that every top-level part has its color(), that they do not overlap, and that your OpenSCAD is a recent version that exports color in 3MF (Requirements). When importing, accept loading it as one object with several parts.

Is there a version for Linux or Intel Macs?

No binaries are published for those platforms. You can try to build from source, unsupported.

Where are my models if I uninstall the app?

In your workspace folders, intact. Only the scadlab.db settings are lost; see Where your data lives.

Can I download it yet?

Yes: the latest version (0.2.0) is on Releases; see Install. You can also build it from source.
